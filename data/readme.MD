| ファイル | 中身 |
|---|---|
| `delish_teiban_photo.json` | **アプリが読むデータ**(`data-adapter.js` の `SOURCE`)。DELISH KITCHEN のレシピ 2468品、写真つき |

| `recipes_kurashiru_100.json` | 名前は「クラシル」だが、中身は `delish_teiban.json` と同じファイル(DELISH のデータ)。アプリ・テストからは使っていない |

データはすべて DELISH KITCHEN(https://delishkitchen.tv/)から授業課題用に取得したもの。公開・再配布はしない。

## delish_teiban_photo.json の作り方

スクレイピングと整形のコードは `temp_koba/delish_pipeline` にある(詳しくはそこの README.md)。

```bash
cd temp_koba/delish_pipeline
bash run_all.sh        # 検索 → レシピ取得 → 写真取得 → build.py → data/ にコピー まで全部
```

- 取る料理のリスト: `dishes.csv`(193品)、`dishes_extra.csv`(170品)、`dishes_extra2.csv`(229品)、`dishes_extra3.csv`(682品。食材名で探す分を含む)
  - 「件数」列で1品あたりの件数を指定できる。同じ料理名をもう一度検索するときは `ハンバーグ#2` のように `#2` を付ける
  - 検索は1ページ目で件数が足りなければ5ページ目まで見る。件数に届かなかった料理は `python collect_urls.py --dishes dishes_extra3.csv --refill` で探し直せる
- どの料理名でどのレシピを取ったか: `urls_map.csv`(「要確認」列に、料理名がタイトルに無かったもの・見つからなかったものの印)
- 材料名の統一・調味料の扱い・分類(カテゴリ・スタイル)の判定・料理でないページの除外: `build.py`
- 代替できる食材の表: `substitutes.csv`(build.py が食材ごとの `substitutes` に入れる)
- 写真: リポジトリ直下の `images/delish/<レシピID>.jpg`(`credits.json` に出典URL)。920px幅のまま、全部で約290MB

データだけ作り直すとき(取得はしない):

```bash
cd temp_koba/delish_pipeline
python3 build.py recipes_urls.json
cp output/recipes_delish.json ../../data/delish_teiban_photo.json
```

## 中身の形式

```
{
  "ingredients": { "鶏もも肉": { "unit", "season", "aliases", "count", "substitutes", "parent" }, "合いびき肉": { ..., "parent", "made_from" }, "鶏肉": { ..., "members" }, ... },   // 食材の一覧
  "recipes": [ { ... }, ... ],
  "meta": { ... }
}
```

レシピの主な項目:

| 項目 | 内容 |
|---|---|
| `id` / `name` / `site_name` | `delish-<サイトのID>` / 料理名 / (同じ料理名のレシピが複数あるときだけ)サイトでの元の名前。2つ目以降の `name` には「かぼちゃの煮物(スピードクック)」のように区別を付けている |
| `category` | 主食・主菜・副菜・汁物・デザート(料理名とタグからの判定) |
| `style` | 和風・洋風・中華・韓国風・エスニック・インド風・メキシカン(料理名・タグ・材料からの判定) |
| `time_min` / `time_capped` / `time_min_uncapped` | サイトの調理時間(上限120分) / 120分で丸めたか / 丸める前のサイトの値(冷やす時間を含むお菓子などは180分以上ある) |
| `price` / `price_source` | 1人前の値段(円) / `site`: サイトの費用目安 ÷ 人数、`computed`: サイトに費用目安が無く、成分表・小売価格から計算した値 |
| `nutrition` / `sugar_g` / `salt_g` | サイトの1人前の栄養(kcal・たんぱく質・脂質・炭水化物)、糖質、塩分 |
| `ingredients` | 食材(`name` は統一した名前、`amount` は1人前の量、`raw` はサイトの表記そのまま) |
| `pantry` / `pantry_variants` | 調味料など家にある前提のもの(足りない食材に数えない) / その元の書き方(「入れたくない食材」の照合用) |
| `steps` / `step_tips` | 作り方(ポイントは「(ポイント: …)」で手順に入れてある) / 手順ごとのポイント |
| `image` / `image_credit` | 写真のパス / 出典 |
| `tools` | 使う器具 |
| `taste_level` / `taste` / `taste_source` | 味の数値(0〜5): `sweet` 甘さ・`spicy` 辛さ・`sour` 酸っぱさ・`salty` しょっぱさ・`rich` こってり度 / 数値から付けた味のラベル / 判定のもと(`llm:qwen3:30b` = ローカルLLM、`rule` = 調味料の量からのルール) |
| `allergens` | 特定原材料8品目(卵・乳・小麦・そば・えび・かに・落花生・くるみ)のうち、材料・調味料の名前から含まれると判定したもの(目安。市販品の原材料は商品で違う) |
| `cook_tags` | 作り方から判定したタグ: `レンジだけ`(加熱は電子レンジだけ)・`火を使わない`・`ワンパン`(フライパンか鍋1つ) |
| `source.url` | 元のレシピのページ |

食材の `substitutes` は「この食材の代わりに使える食材」。アプリはこれをマッチ度の計算に使い、代用できる食材は「足りない」に数えず、代用していることが分かるように「代」マークを出す(全部同じ重みで扱う)。
代替の表は `temp_koba/delish_pipeline/substitutes.csv`(見直しの理由は同じフォルダの `substitutes_review.csv`)。

鶏肉・ひき肉・豆腐・山芋は、サイトに書かれた元の名前で部位・種類に分けている(鶏もも肉・鶏むね肉・手羽元・手羽先・ささみ / 豚ひき肉・合いびき肉・鶏ひき肉・牛ひき肉 / 木綿豆腐・絹豆腐 / 長芋)。
- 分けた食材には `parent`(まとめの名前)がある
- まとめの名前(鶏肉・ひき肉・豆腐)には `members`(部位・種類の一覧)がある。アプリで「鶏肉」と入力すると、全部の部位を持っているとみなす
- 元の名前から部位が分からないもの(「豆腐」とだけ書かれた2品、「山芋」3品)は、まとめの名前のまま。アプリではどの部位でも一致する
- ひき肉には `made_from`(何の肉からできているか。合いびき肉は豚肉・牛肉)がある。アプリで入れたくない食材に「豚肉」と入れると、豚ひき肉・合いびき肉も外す
- 名前を分けるのは栄養・値段を計算したあと(`build.py` の `split_parts`)。ただし計算には元の表記(手羽元・絹豆腐・長芋など)の成分と値段を使うので、部位の違いは計算値にも入っている(対応は `food_map.json`・`nutri/manual_map.py`)。栄養・値段はほとんどがサイトの値で、計算値を使うのはサイトに値がないレシピだけ

## 今のデータの概要

- レシピ 2468品(写真なし 0品)、食材 492種類(うち代替食材あり 61種類、部位・種類で分けた食材 12種類)
- カテゴリ: 主食 470、主菜 1014、副菜 571、汁物 195、デザート 218
- スタイル: 和風 1303、洋風 789、中華 229、韓国風 101、エスニック 25、インド風 12、メキシカン 9
- 調理時間を120分で丸めたもの 96品、価格が計算値のもの 55品
- 料理名(「基本の」「簡単」などを除いた部分)と材料がまったく同じレシピは1品だけ残している(28品を除外。一覧は meta.removed_near_duplicates)
- 味: 全品をローカルLLM(qwen3:30b、`temp_koba/llm/llm_taste.py`)で判定。ラベルの境目は 甘い=甘さ3以上、辛い=辛さ2以上、酸っぱい=酸っぱさ2以上、しょっぱい=しょっぱさ3以上、こってり=こってり度3以上、あっさり=こってり度1以下(`build.py` の `TASTE_LABELS`)。どれにも当たらない料理はラベルなし
  - 品数: しょっぱい 1384、あっさり 834、甘い 648、酸っぱい 514、こってり 482、辛い 259、ラベルなし 68
  - LLM が見落としやすい辛さは、材料に唐辛子・からし・わさび・カレールウなどがあれば最低値を足している(料理名にもその材料があれば2、無ければ1。`build.py` の `spicy_floor`)
  - LLM に置き換える前のルールの値は `temp_koba/llm/out/taste_rule_backup_20261022.csv`、確認用の一覧は `temp_koba/llm/out/taste_check_20261022.csv`
- アレルゲン: 卵 702、乳 642、小麦 1678、えび 99、かに 27、そば 20、くるみ 11、落花生 7(品数)
- 作り方のタグ: ワンパン 1149、火を使わない 147、レンジだけ 143(品数)
- 分類の手直し: ローカルLLM(qwen3:30b)で全品の分類を判定させ(`temp_koba/llm/llm_category_check.py`)、明らかな間違いだけを `build.py` の `CATEGORY_NAME_RULES` で直した。主食→デザート 5品(いちごサンドイッチ・フルーツサンド・基本のミルクレープ・ホットケーキミックスで作るクレープ・りんご蒸しパン)、汁物→主食 4品(スープパスタ2品・とんこつラーメン鍋・シメ雑炊)。LLM の判定はパスタを主菜にするなど間違いが多いので、まとめては反映していない(一覧は `temp_koba/llm/out/category_check.csv`)

## 課題・メモ

- サイトの値のままにしているもの: 汁まで含めた麺類の塩分8g以上、ふきの煮物の塩分11.3g(サイトの誤りかも)、副菜・汁物の1人前25円前後(サイトの費用目安が50〜100円のもの)
- 価格の計算値(`price_source` が `computed`)で高いもの: たたきとろろのすき焼き 1350円(宮崎牛の和牛を使うため)。ブリのしゃぶしゃぶ鍋は「ブリ12切れ」を切り身12枚で計算して2440円になっていたのを直した(薄切り1切れ≒17g)
- 調理時間が手順の書き方と大きくずれる候補は `temp_koba/delish_pipeline/output/time_check.csv`(「丸め」列あり。直すものは build.py の `TIME_OVERRIDES` へ)
- 「適量」の材料は1人前の量を推定している(`estimated`)ので、表示が細かい数字になることがある
- 2000品を超え、アプリの候補一覧(全件を行で描く)と散布図が重く・混みやすい。表示件数を絞るなどアプリ側の工夫が必要
- 写真は約290MB。重ければ480px幅に縮めると約75MBになる(チームで相談中)
